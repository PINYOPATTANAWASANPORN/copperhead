# B0 — harness correctness

Milestone B0 of RFC 11 §13.5 (`openspec/changes/add-pcb-layout-framework`, task 3.8; AC-17.12). Claims, the evidence for each, and how to reproduce it.

- Date: 2026-09-06
- Harness: copperhead 0.10.0 at `946724c`, kicad-cli 10.0.4, node v24.18.0, linux x64
- Engine: `router-reference` 1 (Apache-2.0, in-process, `harnessOnly`, deterministic). The reference router exists to exercise the harness; nothing about board quality is claimed here.
- Suite: `bench/suites/microboards.json` (ten golden microboards, `bench/golden/README.md`)

## Claims

### 1. Repeated runs produce identical harness metrics

Two runs of the suite, same seed, same budget, compared with `copperhead-bench compare` on the selected candidate's metric set (wall-clock metrics excluded by definition). Result: `identicalMetrics: true`.

Per board (run A; run B is identical on every column below):

The candidate boards are identical up to the uuids KiCad regenerates when it saves the refilled board (`test/bench-runner.test.ts` asserts this on two cases every test run). Metrics, diagnostics, ranking, and outcome are computed from the IR, so they are byte-stable regardless.

### 2. Seeded faults are detected

`test/bench-golden.test.ts` verifies every golden board and holds the harness to the `expected.json` of each: the seeded short (`conn.short`), open (`conn.open`), courtyard overlap (`geom.courtyard-overlap`), part outside the outline (`geom.outside-board`), and clearance fault (`drc.clearance`) are each reported with the right entity references, and no unexpected error appears. Four of the ten faults are invisible to KiCad DRC; the harness reports all ten. The keepout, fixed-connector, and decoupling cases need the intent checkers (Phase 3) and are asserted today through KiCad's `items_not_allowed` and through the placement-side metrics only.

With the pre-routing gate landed in this commit, `copperhead pcb route` refuses the overlap and outside-board boards before any engine runs (`REFUSE`, exit 3). The keepout board is routed and then fails the routing gate on KiCad's `items_not_allowed` (`PARTIAL`, board unchanged) until the intent keepout checker lands in Phase 3 and moves it to `REFUSE`. `short` routes only one of its two nets with the reference router; that is the reference router's limit, not a harness finding, and is why it stays `harnessOnly`.

### 3. Engine output cannot modify the source snapshot

`test/pcb-engines.test.ts` runs an out-of-process plugin that writes into its input board; the runner detects the hash change, discards the result, and the outcome is `INVALID_OUTPUT`. Every run directory holds `snapshot.json` (mode 0444) with the hash the job carried; `verifySnapshotIntact` runs after every invocation.

### 4. Complete provenance on every run

Every candidate directory carries `job.json`, `result.json`, `provenance.json` (engine id and version, adapter version, seed, timestamps; for process engines the binary, arguments, and the names of the environment variables passed), `stdout.log`, `diagnostics.json`, and `metrics.json`; the run carries `events.jsonl`, `ranking.json`, and `outcome.json`. Engines receive a scrubbed environment (`test/pcb-engines.test.ts`).

## Reproduce

```bash
npm test -- test/bench-golden.test.ts test/pcb-engines.test.ts test/bench-runner.test.ts
copperhead-bench run bench/suites/microboards.json --routers router-reference --allow-harness-engines --mode single --budget-seconds 120 --track e --out bench/var/runs/B0-a
copperhead-bench run bench/suites/microboards.json --routers router-reference --allow-harness-engines --mode single --budget-seconds 120 --track e --out bench/var/runs/B0-b
copperhead-bench compare bench/var/runs/B0-a bench/var/runs/B0-b
```

`bench/var/` is git-ignored; the reports above are the committed record.
